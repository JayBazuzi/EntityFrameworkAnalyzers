## Code Blocks

NEVER write code blocks directly in the Markdown. Always use `begin-snippet`/`end-snippet` in the test files and let `mdsnippets` generate the code blocks.

Snippets must come from real, compiled code. Never put snippet markers inside a string literal, a `#if false` block, or a comment to show code that isn't compiled: that is a hand-written code block in disguise and can drift from the real API. If an example needs a dependency the tests don't reference, add the dependency and write real code. You may need to create a new csproj to host it, that's fine.

## Generated regions

Markdown files often contain regions that `mdsnippets` overwrites. Never hand-edit the content between these markers; edit the source instead.

| Marker | Source |
| --- | --- |
| `<!-- snippet: Name -->` ... `<!-- endSnippet -->` | `// begin-snippet: Name` ... `// end-snippet` in a test under `test/` |
| `<!-- include: path -->` ... `<!-- endInclude -->` | The included file |

To add a code example, wrap it in `begin-snippet`/`end-snippet` comments in the test file, then add an empty `snippet: Name` line to the Markdown. `mdsnippets` fills in the body and adds `<!-- endSnippet -->`.

Don't wory about udpating/regenerating the snippet in the markdown. CI will update it on any push.

## Two READMEs

`README.md` is the GitHub page; `README.nuget.md` is the NuGet package readme. 

NuGet's renderer is more limited than GitHub's, so avoid HTML, relative images, and GitHub-only syntax (alerts, Mermaid) in `README.nuget.md`.

`README.nuget.md` must not use `snippet:`, because snippets get "snippet source" links to repo paths that break on nuget.org. Instead it uses `include:` on files generated by Verify tests: the rule list comes from `RulesTableTests.RulesList`, and the code example comes from `NugetReadmeTests.Example`, which takes the `DbContextQueryAnalyzerExample` snippet and strips the `{|#0:...|}` markup. Keep prose in the README and only generated content in the verified files.

## Links

CI checks links with `markdown-link-check`. `mlc_config.json` maps root-relative links (`/path`), so prefer root-relative links to repo files in `README.md`. In `README.nuget.md`, use absolute URLs, since NuGet can't resolve repo paths.
